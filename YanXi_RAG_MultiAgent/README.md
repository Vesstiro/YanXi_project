# 言犀 RAG 多Agent增强版

新工程目录：`YanXi_RAG_MultiAgent`。以 **PythonProject2 的真实混合RAG和多Agent处理流程** 为核心，加入 YanXi 的机主状态、号码画像、人工黑白名单、历史和通知能力，保留 YanXi 的独立评测核心，并提供分类结果界面。

两个原工程没有被覆盖。本工程不需要运行时导入任何同级旧工程，也没有复制旧工程的API Key、私人录音、历史报告或向量数据库。

新增 **陌生来电响铃前核验（本地文字模拟）**：左侧“核验资料与题数”填写并授权基础资料和当前事项，选择3/5/7题；“模拟响铃前核验”完成本地问答后显示准确率、覆盖率与接听建议。预留资料用Windows账户加密，原始回答不进入Qwen、历史或导出；联系人跳过。该功能不接入真实电话，也不宣称实现MPC。详细操作与隐私边界见 [核验功能说明](VERIFICATION_README.md)。

## 1. 直接运行

本机已为新工程创建 Python 3.12 虚拟环境，复用系统已有依赖。双击本目录：

- **`启动言犀桌面版.bat`**：日常AI管家，支持文字、麦克风、本地音频、批量处理、查看与朗读。
- **`启动言犀评测台.bat`**：批量录音评测、新来电生成、独立模型评审、JSON/CSV/HTML报告。

首次启动各自填写API Key。日常管家与评测台配置独立；评测台只有在你主动点击读取时，才复用日常管家保存的Key。
当前主界面选择Qwen，默认 `qwen-plus`；同一个管家Key还需有 `text-embedding-v4` 向量模型权限。区域必须与Key匹配。

在项目文件夹的PowerShell中也可运行：

```powershell
.\.venv\Scripts\python.exe desktop.py
.\.venv\Scripts\python.exe evaluation.py
```

新电脑或重建独立环境：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Whisper需要FFmpeg可用。默认 `whisper / turbo`；首次识别模型下载要确认，可先选本机已有的 `small`。
本机默认Whisper所需依赖已存在；Faster-Whisper是可选识别引擎，本次未额外安装，使用它前需安装依赖清单。
Edge TTS联网合成。这里仍是Python源码工程，不是免安装EXE，也没有接管真实电话线路。

## 2. 机主状态与号码管理

管家主界面左侧点击 **“机主与号码管理”**：

| 页面 | 内容 |
| --- | --- |
| 状态与授权 | 空闲、忙碌、免打扰、驾车；原因与持续时间；明确授权投递点、有限餐品替换、回电说明 |
| 联系人与名单 | 输入号码、用户备注名、普通/白名单/黑名单、可选人工参考分、备注；查看历史分和来电次数 |
| 来电历史 | 最近100次分析的号码、状态、处理建议、回复、通知与检索/Agent结果 |

默认不假定机主在上课，不默认“北门”，也不默认允许改餐、付款或退款。
“允许餐品替换”仅限无额外费用、同价同类，不包括补差价、取消、退款、付款、借钱或改约。
计时结束恢复空闲，投递位置等长期授权仍保留；需要取消授权时请手动清除或取消勾选。

状态、名单和授权在正在处理时不能修改，避免同一次分析读到前后矛盾的设置。
每次分析前重新读取状态，所以手动设置和到期恢复均会真正进入Agent上下文。

号码可在主界面输入。中国手机的 `+86`、空格和短横线写法会归一；不把不明号码或分机随便合并；空号码不建立共享匿名画像。
历史分是0–100的行为参考，初始50，不是“身份真实概率”。白名单是人工偏好，**不能覆盖本次诈骗风险**；驾车期间也不会因白名单而建议即时接听。
手动黑名单直接产生拒接建议，不调用RAG或模型，也不会把这一行为当成“模型确认诈骗”。

## 3. 真正执行的处理流程

```text
文字 / 录音本地ASR
        ↓
本次机主状态 + 本地号码资料（与来电者自述区分）
        ↓
PythonProject2混合RAG：字符n-gram + Qwen向量 + Chroma → Top5
        ↓
深度场景Agent → 风险Agent
        ├─ 高风险/营销 → 拒绝建议
        ├─ 需要机主判断 → 人工确认/留言Agent
        └─ 可处理事项 → 业务Agent → 必要时升级人工确认
        ↓
最终状态/权限检查 → 文字回复 + 通知卡片 + 号码与来电记录
```

核心不是旧YanXi的关键词分类器换皮。每条正常模型链路先做实际向量检索，再调用场景、风险以及业务或人工确认Agent；处理角色和顺序来自PythonProject2。
所有主Agent通过统一模型客户端，以便原评测台跟踪调用和异常。JSON缺字段、模型失败、向量失败都报错，不伪装成正常完成。

“检索 / Agent”页展示知识命中、来源、分数、各阶段的结构化分析与最终策略。它是可审查的程序输出，不是模型隐藏思维链。

### RAG与知识库

- 保留原2/3/4/5-gram倒排候选、最多30条精筛、向量Top10、融合加权及最终Top5算法。
- 知识库来自 `PythonProject2/data/knowledge.txt`，原样复制到 `assets/knowledge.txt`。
- 共502行，其中500条有效；第9、24行格式异常，跳过并显示诊断，没有偷偷修补或使用测试参考答案替代。
- Qwen向量模型默认 `text-embedding-v4 / 1024维`，配置位于 `config.yaml`。
- 知识、区域、模型、维度变化会产生新指纹缓存；不删除旧缓存，半成品不会当成完整索引。
- 评测每案例仍有独立Chroma目录。同一进程只复用不可变的知识文档向量；不共享来电查询、号码、授权或历史。
- 报告中的 `knowledge_sha256` 和 `rag_diagnostics` 记录知识版本、跳过行、缓存及检索配置。

沿用的知识库包含早期“上课”“北门”“自动同意”等过强规则。新提示词明确把它们当参考例子，当前机主设置和权限高于这些规则。
没有沿用“补差价/借钱关键词强制降风险”、冒充本人回复、无授权付款改约、声称已报警等旧行为。

## 4. 评测规则保留，生成续批修复与结果分类展示

评分门槛、统计、服务、配置和报告等五个原核心文件与原 `YanXi_project/src/evaluation/` 保持一致；没有修改评审提示词、四维门槛、错误统计或导出报告格式。生成器保留词面与独立语义双重去重，但修复了“一批候选全部判重后，后续继续返回同一批内容”的问题：每轮轮换场景方向，并把已拒候选加入避让记忆，因此可继续生成超过首批5条。
根据新的界面需求，`app.py` 改为页签式展示，并新增纯展示模块 `presentation.py`。结果分为：**直接回复、评测评价、评分依据、判断过程、原文/转写、运行详情、原始数据**，可复制当前页。
“直接回复”仅显示管家原话，评测AI的改写建议单独标明；“判断过程”展示已记录的RAG与Agent结构化依据，不编造隐藏思维链。旧JSON报告也可直接载入，无需重新调用API。
评测调用的 `CallOrchestrator` 接口实现为新主程序核心。日常管家和评测调用的是同一套真实处理逻辑，不是专门给评测返回的答案。

保留：

- 录音→ASR、配套文本、合成文本、合成语音→ASR四种模式。
- 数据集导入、筛选、选中/批量、重试、停止、历史恢复。
- 新场景生成、词面检查、独立语义去重，以及生成后人工确认再评测。
- 独立评审Key和模型、四项0–5评分、低置信度/缺原文待复核、错误和降级单列。
- 每例独立单轮、空闲机主、空号码、无历史/白名单/额外授权；不会读入日常机主设置。
- 通过率分母仍为“通过+不通过”，不把待复核、错误等混入。
- 连续3个错误或API降级自动停，逐案例保存，导出JSON/CSV/HTML。

完整操作见 [评测使用说明](EVALUATION_README.md)。附带262段测试音频和200份参考原文；缺原文的62段仍需人工核听。

### 怎样验证正确率是否真的提高

先在新旧评测台各选同样的2–3条、有配套原文的录音。保持相同管家模型、评审模型、识别模型和输入模式，比较回复、四维证据、通过率与错误率。
测试管家逻辑可先用配套文本排除ASR干扰；验证语音端到端则必须用录音模式，不能混为一谈。
忙碌/驾车/号码名单有单独业务测试；原评测基线仍固定空闲，不能据它宣称所有状态正确率。

**本次没有执行付费的大批量真实API评测，尚无证据宣称新版本正确率已经提升。** 模型评审也可能偏差；高风险和紧急案例要人工复核。

## 5. 费用、隐私与边界

- 首次完整知识向量化500条，按每批最多10条请求；每个来电另有查询向量请求，再进行多Agent对话。
- 原评测 `sut_api_calls` 只计主Agent对话请求，不含向量请求；不要把它当百炼账单中的全部调用数。
- 首次大批量前先少量试跑；新进程或新知识版本可能重新生成文档向量，缓存命中情况可在诊断中查看。
- 语音本地识别；来电文字、必要号码资料、机主提供的上下文与知识示例会用于Qwen调用；知识示例也用于向量API。朗读文字发往Edge TTS。
- Key保存在本地明文 `.env` 或 `data/evaluation/.env`，不是加密保险库；分享前排除整个 `data/`、`.env`、`.venv/` 和缓存。
- 记录中的来电是模拟分析次数，不是电话网络证实的接听次数；重复人工分析会产生新记录。
- 保存异常会显示明确警告，保留已生成结果供手动导出，不伪装为模型处理失败而自动重跑。
- 所有转接、拒接、提醒均为界面建议；没有实际通话、短信或报警能力。
- 规则检查不能证明任意自然语言回复完全安全；仍需持续采样、复核和改进。

## 6. 工程结构与验证

```text
desktop.py / evaluation.py       两个可视化入口
src/assistant/                  场景、风险、业务、人工确认、统一调度和权限策略
src/rag/                        Qwen向量适配、Chroma及n-gram融合
src/context/                    机主状态、联系人/信任/名单、历史存储
src/orchestration/              新核心兼容门面（原评测接口不变）
src/desktop/                    日常GUI、设置、语音、管理窗口
src/evaluation/                 五个原评测核心文件 + 续批生成修复 + 分类GUI与纯展示模块
src/core/ + src/utils/           模型客户端、枚举、配置、实例级状态等
src/knowledge/                  原习惯模块兼容符号，不用于自动覆盖当前机主状态
assets/knowledge.txt             PythonProject2原知识规则
test_audio_batch_200/            262音频及200参考原文
tests/                          原界面/评测回归与新RAG、状态、策略测试
data/                           本机设置、向量缓存、联系人、来电与评测记录（自动生成，不分享）
```

运行全部离线测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
```

包含真实本地Chroma配合假向量API的子进程测试、实际主调度配合假模型的集成测试、状态/名单/权限测试、原评测评分与报告测试、六个核心文件一致性检查及结果分类展示测试。
通过测试不代表麦克风权限、真实API连通性、真实模型质量或TTS网络都已验证。
